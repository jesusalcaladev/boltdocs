## Ya está aquí Boltdocs 3.3.0

Boltdocs 3.3.0 continúa el trabajo de Nitro iniciado en 3.1.0 y 3.2.0: menos trabajo durante el arranque, mejor concurrencia y menos supuestos dentro del core. También incorpora APIs opt-in para tener más control sobre SEO, transiciones y páginas personalizadas.

<Callout type="info">
  En el sitio de benchmark de 100 páginas, el cold build de 3.3.0 bajó de **17.85s a 14.50s** comparado con la corrida publicada anterior (un ~19% más rápido), el arranque dev mejoró a **5.3s** y los warm builds terminan en **3.1s**. Son resultados de benchmark, no una garantía para cada proyecto; consulta la [página de rendimiento](/es/benchmark) para ver la metodología y los resultados actuales.
</Callout>

## Builds y arranque más rápidos

3.3.0 mueve más trabajo fuera de la ruta crítica de inicio. En el sitio de benchmark de 100 páginas, el cold build bajó de **17.85s a 14.50s** y el arranque dev de **5.5s a 5.3s** comparado con la corrida publicada anterior:

- **Precompilación temprana de Sätteri**: comienza desde `configResolved()` para que los workers preparen MDX mientras Vite inicializa su grafo.
- **Pools dinámicos de workers**: evita saturar máquinas pequeñas con un número fijo de workers. El pool escala según CPU y cantidad de archivos.
- **Arranque dev no bloqueante**: el servidor empieza a escuchar antes de que termine la generación de rutas en segundo plano.

La comparación completa está en la [página de rendimiento](/es/benchmark). Úsala como referencia reproducible, no como promesa para una aplicación concreta.

## Un core agnóstico a CSS

El core ya no supone que cada proyecto usa Tailwind CSS. Vanilla CSS, CSS Modules, custom properties y los tokens del tema funcionan sin agregar un framework CSS.

Las integraciones CSS ahora son plugins explícitos:

| Paquete | Propósito |
| :--- | :--- |
| [`@bdocs/plugin-tailwindcss`](/es/plugins/css/tailwindcss) | Tailwind CSS v4 mediante la integración de Vite. |
| [`@bdocs/plugin-sass`](/es/plugins/css/sass) | Preprocesamiento SASS y SCSS. |
| [`@bdocs/plugin-unocss`](/es/plugins/css/unocss) | Utilidades atómicas de UnoCSS. |

Por ejemplo:

```ts title="boltdocs.config.ts"
import { defineConfig } from 'boltdocs'
import tailwindcssPlugin from '@bdocs/plugin-tailwindcss'

export default defineConfig({
  plugins: [tailwindcssPlugin()],
})
```

## La nueva API de plugins

La API `definePlugin` ofrece hooks tipados y puntos de extensión claros para UI cliente, providers, frontmatter, indexación de búsqueda y assets posteriores al build.

```ts
import { definePlugin } from 'boltdocs'

export default definePlugin(() => ({
  name: 'my-plugin',
  hooks: {
    'frontmatter:transform'(_ctx, { frontmatter, rawContent }) {
      return {
        ...frontmatter,
        readingTime: Math.ceil(rawContent.split(/\s+/).length / 200),
      }
    },
    'build:generate'(ctx, { routes, outDir }) {
      ctx.logger.info(`Generated assets for ${routes.length} routes in ${outDir}.`)
    },
  },
}))
```

Consulta la [referencia de la API de plugins](/es/api/plugin-api) para la lista completa de hooks y namespaces.

## APIs opt-in para SEO y páginas

### Structured Data (JSON-LD)

JSON-LD pertenece al SEO y la descubribilidad, no al diálogo de búsqueda interno. Configura un graph global con helpers importados desde el entrypoint de Node:

```ts
import {
  createWebSiteStructuredData,
  defineConfig,
  defineStructuredData,
} from 'boltdocs'

export default defineConfig({
  siteUrl: 'https://example.com',
  seo: {
    structuredData: defineStructuredData(
      createWebSiteStructuredData({
        name: 'Example Docs',
        url: 'https://example.com',
      }),
    ),
  },
})
```

Usa `seo.structuredData` en el frontmatter para datos específicos de una página o renderiza `<StructuredData data={...} />` desde una página React externa. Consulta la [guía SEO](/es/integrations/seo) para helpers de artículos y breadcrumbs.

### View Transitions

Las View Transitions son opt-in y vuelven a una actualización normal cuando el navegador no implementa `document.startViewTransition`:

```ts
export default defineConfig({
  experimental: {
    viewTransitions: {
      enabled: true,
      types: ['page'],
    },
  },
})
```

Los layouts personalizados y las páginas externas pueden llamar `useViewTransition()` desde `boltdocs/client`. Consulta [Funciones Experimentales](/docs/es/guides/advanced/experimental).

### File-routing estático en `pages-external`

Un proyecto puede activar rutas de archivos literales sin construir un único objeto `pages`:

```text
docs/pages-external/
├── home.tsx      → /home
├── about.tsx     → /about
└── pricing.mdx   → /pricing
```

Actívalo con `experimental.fileRouting`. En esta primera versión se ignoran intencionalmente los segmentos dinámicos como `[id]`, los grupos de rutas y los archivos auxiliares reservados. La API existente de `pages-external/index.tsx` sigue disponible. La [guía de Páginas Externas](/docs/es/guides/customization/external-pages) cubre ambas APIs.

## Las colecciones muestran primero las publicaciones recientes

Las publicaciones de colecciones ahora se ordenan por fecha de publicación descendente. Las nuevas aparecen primero y las fechas ausentes o inválidas quedan después de las publicaciones fechadas. Esto aplica a `usePosts()`, `useRecentPosts()`, los datos virtuales de colecciones y la paginación de la plantilla de blog.

## Una auditoría de seguridad de plugins más precisa

`boltdocs audit` — el escaneo estático que inspecciona los plugins instalados en busca de llamadas riesgosas **sin ejecutarlos nunca** — recibió una ronda de mejoras de corrección y rendimiento:

- **Resolución precisa de plugins.** Los plugins ahora se emparejan con sus paquetes instalados mediante los specifiers de import del config, así los paquetes con scope se resuelven correctamente aunque el `name` del plugin difiera del nombre del paquete. `boltdocs-plugin-mermaid` ahora audita `@bdocs/plugin-mermaid` en lugar de reportar `Unresolved`.
- **Escaneos acotados.** Cada plugin se escanea dentro de un presupuesto total de bytes (8 MB por defecto). Si un bundle minificado enorme cruza el presupuesto, el escaneo se detiene y reporta un hallazgo `scan-truncated` — un escaneo incompleto nunca se reporta como limpio.
- **Resúmenes fail-closed.** Los plugins que no se pueden resolver o escanear se tratan como no confiables y nunca cuentan para "todos los plugins pasaron".
- **Arranque más rápido.** La auditoría carga solo `config.plugins` (saltándose la validación completa de configuración), filtra el catálogo de reglas con un pre-paso de rechazo rápido, y `--help`/`--version` ya no cargan el toolkit de UI — el CLI arranca aproximadamente un 30% más rápido.

Ejecútalo antes de agregar un plugin de terceros:

```bash
boltdocs audit
```

El escaneo reporta llamadas a child-process y código dinámico, acceso de red, lectura y escritura de archivos, acceso a variables de entorno y banderas rojas de metadatos (scripts de instalación, dependencias empaquetadas, licencia o procedencia ausente). Consulta la [referencia del CLI](/docs/es/guides/getting-started/cli) para el formato completo de salida, incluido el contrato de exit codes para CI.

## Actualización

```bash
pnpm add boltdocs@latest @bdocs/ssg@latest
```

Si usas un framework CSS, instala también el plugin correspondiente. Los proyectos existentes pueden actualizar sin activar flags experimentales: `viewTransitions` y `fileRouting` siguen siendo opt-in.
